Chapter 1.1

Excel foundations

The aim of this chapter is not "learn Excel". It is to make the grid stop being mysterious, so that when a later lesson says put this in N2 and fill it down, you do it without thinking. Nine lessons. Every one has something to type.

How the grids work. Click a cell. Its address appears on the left of the bar above the grid and its contents appear in the bar itself. Type to replace, press Enter to confirm, Esc to abandon. Arrow keys move. The small green square at the bottom-right of the selected cell is the fill handle — drag it down. Grey cells are locked so the practice data cannot be broken by accident; cells with a gold outline are the exercise.

The furniture

Workbook, sheet, cell, range

A workbook is the file. A worksheet is one tab inside it. A cell is a single box, named by its column letter then its row number: D2. A range is a rectangular block, written with a colon: A1:L7 means every cell from A1 down-and-across to L7.

Your real workbook will have three sheets, and this is worth deciding now because changing it later is painful:

SheetWhat lives on itRule
CandidatesOne row per person. Every fact about that person.Nothing but data. No totals, no blank spacer rows, no notes in the margin.
RolesOne row per requisition.Same rule. This is the small table the big one looks things up in.
DashboardOnly formulas and charts that point at the other two.Never type a number here. If a number is typed here, it will one day be wrong and nobody will know.

That separation — data on one sheet, answers on another — is the single habit that distinguishes a spreadsheet someone can trust from one they cannot. It is also the exact idea Power BI is built on, so learning it here makes chapter 2 easier.

Why a range matters more than it looks. E2:E7 is six cells. If you later insert a row inside it, Excel stretches the range for you. If you insert a row below it, it does not stretch, and the formula silently misses the new person. That single behaviour is why lesson 6 exists.

The thing beginners lose days to

Three data types, and how to tell which one you have

Excel holds exactly three kinds of thing, and almost every "Excel is broken" moment is one of them being the wrong one.

Number

Right-aligned by default. Can be added, averaged, compared. 4000.

Text

Left-aligned by default. Cannot be added. LinkedIn, and also "4000 " with a space in it.

Date

Right-aligned, because a date is a number wearing a costume. Next lesson.

The alignment test. Type something and look at which side of the cell it sits on. If a column of numbers has one value hugging the left edge, that value is text, and every SUM in the file is already wrong. No warning appears. This is the most common real-world data bug in HR reporting, because exports from an ATS routinely deliver numbers as text.

Two ways to tell for certain, and both are worth knowing:

  • =ISNUMBER(A2) returns TRUE or FALSE. Blunt and reliable.
  • =ISTEXT(A2) for the opposite. A number stored as text returns TRUE here, which is the moment the penny drops.

And two ways to fix it: multiply by 1, or run =VALUE(A2). In a real export, Power Query's Change Type step (lesson 1.4) fixes the whole column at once and keeps fixing it every month.

Worked example

Column B below looks like a column of fees. It is not. B3 and B5 were typed with a trailing space, which makes them text. Column C shows the test, column D shows the fix.

The SUM in B8 ignores the two text cells and reports 1,000. The SUM in D8, over the converted column, reports the true 8,000 — and no error or warning appeared anywhere. In a report to a hiring manager, a missing €7,000 of agency spend is a credibility event.

Everything in recruiting is a date difference

Dates are numbers

Excel stores a date as a count of days since the start of 1900. 2 March 2026 is the number 46083. The date you see is a format laid over that number, exactly like €4,000 is a format over 4000. The grid below proves it — column I is the same dates with the costume taken off.

This one fact explains the whole of recruiting analytics:

= Accepted - Applied → 46106 − 46083 → 23

Time to hire is not a special function. It is subtraction. Every metric in chapter 3 is this idea with a different pair of columns.

Which also explains the failures:

What you seeWhat happenedFix
46083 where a date should beThe cell is formatted as a number. The value is right.Format the cell as a date. Ctrl+1.
#VALUE! when subtractingOne "date" is text. Often it arrived as 02-03-2026 from a system that uses a different locale.=DATEVALUE(), or fix the type in Power Query.
A negative durationThe dates are the wrong way round, or someone typed the offer date before the application date.Wrap it: =IF(I2<E2,"check dates",I2-E2).
A huge negative numberYou subtracted a date from a blank. A blank counts as zero, so the answer is minus 46,000-odd.Test for the blank first. That is the next lesson's IF.

Never type a space into a cell to mean "nothing happened". A space is text. It breaks the subtraction, it breaks COUNT, and it is invisible. Leave the cell genuinely empty. This is why the practice data has real blanks for Farah.

The date functions worth knowing, in order of usefulness to you. TODAY() for ageing a pipeline. So the arithmetic is never a surprise

Operators and the order they run in

A formula always starts with =. That is how Excel knows to calculate rather than store. Everything after it is built from these:

OperatorDoesExample
+ - * /Arithmetic=3*4 → 12
^Power=2^3 → 8
%Divides by 100=10% → 0.1
&Joins text="Asha"&" · "&"LinkedIn"
= <> < > <= >=Compares, returning TRUE or FALSE=C2="LinkedIn" → TRUE

The order is the one from school: powers, then multiply and divide, then add and subtract. =2+3*4 is 14, not 20. Parentheses override it, and in a recruiting formula they are nearly always needed, because a rate is a division of a sum:

=(B2+B3)/C2 not =B2+B3/C2

Percentages are where this bites. An offer acceptance rate of 3 out of 4 is =3/4, which is 0.75. It is not 75 until a format is applied. If you type =3/4*100 and then formats as a percentage, you get 7500%. Pick one: calculate the ratio and format as percent, or calculate the ratio times 100 and label it "%". The first is correct Excel practice, because charts and Power BI both expect the ratio.

ROUND changes the value, formatting only changes the display. =ROUND(31.333,1) really is 31.3 and will add up as 31.3. A cell formatted to one decimal still holds 31.3333 and will add up as that. For a number going into a report, round it — so that the parts visibly sum to the total you are showing.

The reason a formula breaks when copied

Relative, absolute and mixed references

When a formula is copied down a column, Excel moves its references with it. That is usually exactly what is wanted — row 2's formula should look at row 2 — and occasionally catastrophic.

WrittenCalledWhen copied downUse for
E2RelativeBecomes E3, E4, E5The normal case: this row's data.
$E$2AbsoluteStays E2 foreverOne fixed cell everything divides by — a total, a target, a conversion rate.
E$2Mixed, row lockedColumn can move, row cannotCopying across a row of months.
$E2Mixed, column lockedRow can move, column cannotRare in your work. Recognise it.

The F4 key cycles a reference through all four states while editing — on a Mac, fn+F4 or Cmd+T. Worth learning, because typing dollar signs by hand is how typos happen.

Do this before writing a single formula

Tables and structured references

Select the data and press Ctrl+T — Cmd+T on a Mac — tick "my table has headers", then rename it in Table Design to Candidates. It takes four seconds and changes five things:

  1. New rows are included automatically. Add a seventh candidate and every formula, chart and PivotTable that points at the table already knows. This is the big one. Range-based files break the week someone adds a row.
  2. Formulas read like English. Candidates[Source] instead of C2:C7. Six months later you can still tell what the formula means.
  3. Filter buttons appear on every header.
  4. The header row freezes when scrolling.
  5. Formulas fill down the column by themselves when typed in the first row.

Inside a table, [@Applied] means "the Applied cell on this row". So the time-to-hire column becomes:

=IF([@Accepted]="","",[@Accepted]-[@Applied])

That is the same formula as =IF(I2="","",I2-E2), and it is better for one reason beyond readability: if someone inserts a column, it still points at the right thing. The letter-based version points at whatever is now in column I.

SyntaxMeans
Candidates[Source]The whole Source column, data only, growing as rows are added.
[@Source]The Source cell on the current row. Only valid inside the table, or beside it.
Candidates[#Headers]The header row. Occasionally useful, rarely needed.
Candidates[#All]Headers plus data. Mostly appears by accident when clicking.

One trap. A table cannot contain a blank row in the middle, and it should not contain merged cells. Merged cells break sorting, filtering, PivotTables and copy-paste. There is no situation in a data sheet where merging is the right answer. Centre across selection if it has to look pretty.

So an error is information, not a wall

Reading the seven errors

Every Excel error names its own cause. Learning the seven means never again deleting a formula and starting over.

ErrorIt meansIn your file it will be because
#DIV/0!Divided by zero or by a blank.An acceptance rate for a role with no offers yet. Wrap it in IFERROR.
#N/AA lookup found nothing.A RoleID typo — BE1 instead of BE-1, or a trailing space.
#VALUE!The wrong type of thing.Text where a number belongs. Usually a date that arrived as text.
#NAME?Excel does not recognise a word.A misspelled function, a missing quote mark, or XLOOKUP in an old Excel.
#REF!The reference no longer exists.Someone deleted a column the formula pointed at.
#SPILL!A dynamic array has nowhere to land.Something is already sitting in the cells below a FILTER.
#####Not an error at all.The column is too narrow. Double-click the column edge.

IFERROR is a tool and a temptation. =IFERROR(x,"") hides the error, which is right when the error is expected — a rate with no denominator yet. It is wrong when the error means the data is broken, because it hides that too. The rule: wrap divisions, investigate lookups.

So it survives being read by a stranger

Formatting that earns its keep

Formatting is not decoration here. It is the difference between a hiring manager understanding a number and asking your to explain it.

  • Number formats. Ctrl+1. Dates as dd mmm yyyy, because 03/02/2026 means two different days in Dublin and Chicago. Percentages to nought or one decimal, never four. Currency with the € symbol so nobody has to ask. Durations as plain numbers with the word "days" in the column heading, not in the cells.
  • Freeze panes. View > Freeze Panes > Freeze Top Row. Non-negotiable on any sheet longer than a screen. A table (lesson 6) does this for free.
  • Wrap text and autofit. Double-click the right-hand edge of a column header to autofit it. Wrap the header row, not the data.
  • Column headings are names, not sentences. HireDays, not No. of days taken to hire the candidate. The long version belongs in a Notes cell at the top of the sheet.
  • One font, two sizes, three colours. Bold the header row, right-align the numbers, and stop. A spreadsheet with a rainbow in it reads as uncertain.
  • Print setup, because someone will print it. Page Layout > Fit to one page wide, landscape, and set Print Titles so the header repeats on every page.

Two things never to do in a data sheet. Never merge cells — it breaks sorting, filtering and PivotTables, and there is always a better option. Never use colour as the only carrier of meaning; put the word in a column too, because colour does not survive a photocopy, a colour-blind reader, or a PivotTable.
