Chapter 1.3

Lookups and text

Two tables have to talk to each other, and real data arrives dirty. This chapter is the difference between a spreadsheet that works on the practice data and one that survives an actual ATS export.

The one lookup worth learning

XLOOKUP

The Candidates table knows a RoleID — BE-1. The Roles table knows that BE-1 is a Backend Engineer in Dublin whose hiring manager is Maya Shah. XLOOKUP carries facts from the small table to the big one.

=XLOOKUP( what to look for , where to look , what to bring back , what if not found )

Read it as a sentence: look for this RoleID, in the Roles table's RoleID column, and bring me back the matching HiringManager; if there is no match, say "No role".

=XLOOKUP([@RoleID], Roles[RoleID], Roles[HiringManager], "No role")

The fourth argument is the one everybody skips, and it is the most valuable. Without it, a typo'd RoleID gives #N/A, which is correct but ugly, and in a column of 400 rows it is noise. With "No role", the broken rows are instantly readable and filterable — you can filter the column to "No role" and see exactly which records need fixing. That turns an error into a worklist.

Why it beat VLOOKUPDetail
It looks in any directionVLOOKUP can only return a column to the right of the key. XLOOKUP does not care.
No column countingVLOOKUP needs "the 4th column". Insert a column and it silently returns the wrong field. XLOOKUP names the column it wants.
Exact match by defaultVLOOKUP defaults to approximate, which is how a wrong-but-plausible answer gets into a report with nobody noticing.
Built-in not-foundNo IFERROR wrapper needed, so a genuine error is still visible.

Reading other people's files

VLOOKUP and INDEX/MATCH

You should not write these. You will absolutely have to read them, because every file you inherit is full of them.

VLOOKUP, decoded

=VLOOKUP( key , whole block including the key column , which column number to return , FALSE for exact )

The two things to check whenever you see one. First, is the last argument FALSE or 0? If it is TRUE or missing, it is doing an approximate match on unsorted data, and the answers may be quietly wrong. Second, count the columns — 3 means the third column of the block, not of the sheet, and if anyone has inserted a column since it was written, it is now returning the wrong field.

INDEX and MATCH, decoded

Two simple functions that combine into a lookup. Each is useful alone:

  • =MATCH("FE-1", Roles[RoleID], 0) → 2. "Which position is this in?" The 0 means exact match, and it should always be there.
  • =INDEX(Roles[Title], 2) → Frontend Engineer. "Give me the item at position 2."
  • Nest them: =INDEX(Roles[Title], MATCH([@RoleID], Roles[RoleID], 0)) — find the position, then fetch the value at it.

Read from the inside out, always. MATCH runs first and hands its answer to INDEX. This combination was the correct professional answer for twenty years before XLOOKUP existed, which is why it is everywhere.

What to say in an interview if asked which you use. "XLOOKUP, because it is exact by default and does not break when someone inserts a column. I can read VLOOKUP and INDEX/MATCH in existing files, and if a company is on an older Excel I use INDEX/MATCH." That answer says you know all three and has a reason for your choice, which is the actual question being asked.

Real exports are filthy

Cleaning text

Here is what an ATS export of a Source column actually looks like, and what each problem does:

ValueProblemConsequence
LinkedInNone—
referral Trailing space, lower caseCOUNTIF on "Referral" misses it. Case is fine — COUNTIF ignores it — but the space is fatal.
LinkdinTypo at the sourceAppears as a separate source in every PivotTable. The one a formula cannot fix.
 LINKEDINLeading space, shoutingSame as above.

Four values, one real source, and a PivotTable that reports four sources. The fixes:

  • TRIM removes leading, trailing and doubled-up spaces. Run it on every text column of every export, always.
  • CLEAN strips non-printing characters — the invisible junk a CSV from an old system leaves behind.
  • PROPER gives Title Case, UPPER and LOWER the obvious. PROPER on "LINKEDIN" gives "Linkedin", not "LinkedIn" — so for a fixed list of known values, a lookup is better than a case function.
  • LEN is the diagnostic. =LEN(A2) against a value that looks like 8 characters and reports 9 has found the invisible space.
  • SUBSTITUTE fixes a known typo: =SUBSTITUTE(A2,"Linkdin","LinkedIn"). Fine for one known error, unmanageable for twenty — at that point build a small mapping table and XLOOKUP it, which is the exercise below.

The professional move is to not do this by hand every month. One TRIM column is fine once. A monthly export needs Power Query, where the cleaning steps are recorded and replay themselves on every refresh. That is lesson 1.4.

Your turn — clean a real-looking mess

One column holding two facts

Splitting text apart

Job titles arrive as Backend Engineer - Dublin. You need the title and the city as separate columns, because nothing can be grouped or filtered while they are glued together.

FunctionDoesOn "Backend Engineer - Dublin"
LEFT(text, n)First n characters=LEFT(A2,7) → Backend
RIGHT(text, n)Last n characters=RIGHT(A2,6) → Dublin
MID(text, start, n)n characters from a position=MID(A2,20,6) → Dublin
FIND / SEARCHThe position of something. FIND is case-sensitive, SEARCH is not and allows wildcards.=SEARCH("-",A2) → 18
TEXTBEFORE / TEXTAFTEREverything before or after a delimiter. Microsoft 365 only.=TEXTBEFORE(A2," - ") → Backend Engineer

Counting characters by hand — LEFT(A2,16) — works until a title is a different length. The robust version finds the separator and measures from it:

=TRIM(LEFT(A2, SEARCH("-",A2)-1)) everything before the dash =TRIM(MID(A2, SEARCH("-",A2)+1, 99)) everything after it

Read the first one from the inside: SEARCH finds the dash at 18, minus 1 is 17, LEFT takes 17 characters, TRIM removes the trailing space. It survives any title length. TEXTBEFORE and TEXTAFTER do the same thing in one step and should be preferred when available — but the SEARCH version is worth understanding, because it is what you will find in other people's files.

Two faster ways when it is a one-off. Flash Fill (Ctrl+E): type the answer for the first row, start typing the second, and Excel offers the rest. It is magic, it is not a formula, and it does not update when the data changes — fine for a one-off, wrong for a monthly file. Text to Columns (Data ribbon) splits a whole column by a delimiter in one go, overwriting as it lands. Both are good tools. Neither belongs in a file that refreshes.

Labels and messages

Joining text back together

  • & is the quickest: =A2&" · "&C2 → Asha · LinkedIn. Spaces and punctuation must be inside quotes, which is the thing people forget.
  • CONCAT joins a list or a range. No separators.
  • TEXTJOIN(separator, ignore_blanks, …) is the useful one. The second argument TRUE skips empty cells, which means no stray commas.
=TEXTJOIN(", ", TRUE, Candidates[Name]) → Asha, Ben, Cara, Dev, Eva, Farah

Where this earns its keep is a dynamic summary line on the dashboard — a sentence that rewrites itself when the data changes:

="Still open: "&TEXTJOIN(", ",TRUE,FILTER(Candidates[Name],Candidates[Outcome]="Open"))

That is one cell that always says who is outstanding. Combined with the number format trick — &TEXT(value,"0%") to put a formatted number inside a sentence — you can write a dashboard headline that never goes stale:

="Acceptance "&TEXT(B9,"0%")&" across "&B5&" offers"

Why TEXT is needed there. Joining a number into text loses its formatting — ="Rate "&0.75 gives Rate 0.75, not Rate 75%. TEXT(B9,"0%") applies the format as part of the join. This is the single most common reason a dashboard headline looks half-finished.

Modern Excel, and it is genuinely better

FILTER, UNIQUE and SORT

These return several answers from one formula. Type it in one cell and the results "spill" into the cells below, with a faint border round the block. Change the data and the block resizes itself. There is no equivalent in older Excel, which is why this course asks for Microsoft 365.

FormulaReturns
=FILTER(Candidates[Name], Candidates[Outcome]="Open")Farah
=FILTER(Candidates[Name], Candidates[Screened]="")Everyone never screened — the Monday list
=UNIQUE(Candidates[Source])LinkedIn, Referral, Agency — the distinct values
=SORT(UNIQUE(Candidates[Source]))The same three, alphabetically
=COUNTA(UNIQUE(Candidates[Source]))3 — how many different sources are in use

The combination worth remembering is UNIQUE down the side, COUNTIFS across. That builds a live summary table without a PivotTable, and unlike a PivotTable it never needs refreshing:

N2: =SORT(UNIQUE(Candidates[Source])) spills the source names O2: =COUNTIFS(Candidates[Source], N2#) counts each one

The # in N2# means "the whole spilled block that starts at N2". So when a fourth source appears in the data, both columns grow together. That is a self-maintaining report.

#SPILL! means the result needs cells that are not empty. Something is in the way below the formula. Clear the obstruction — do not shorten the formula. And a dynamic array cannot spill inside a Table, so these live beside the table, not in it.

The chapter's deliverable

Enriching the Candidates table

Everything so far, in one place. The finished Candidates sheet has five calculated columns, and this is the exact set you should be able to rebuild from a blank sheet before you leave this chapter.

ColumnFormulaWhy it exists
HireDays=IF([@Accepted]="","",[@Accepted]-[@Applied])Time to hire per person.
Manager=XLOOKUP([@RoleID],Roles[RoleID],Roles[HiringManager],"No role")So you can group by manager without typing it 400 times.
City=XLOOKUP([@RoleID],Roles[RoleID],Roles[Location],"?")Location reporting, and a map in Power BI later.
Chase=IF(AND([@Outcome]="Open",TODAY()-[@Applied]>14),"CHASE","")Your Monday morning list.
Label=[@Name]&" · "&[@Source]&" · "&[@Outcome]A readable one-line summary for a chart tooltip or a message.

Note that not one of them contains a typed fact. Every one is derived. That is the standard: if a human typed it, it is data and it belongs in columns A to L; if Excel worked it out, it is a formula and it belongs to the right.

Before moving on

From a blank sheet: an XLOOKUP with a sensible not-found message, a TRIM-and-map clean of a dirty source column, a split of a title from a city, and a FILTER that lists who is still open. Then be able to say in one sentence why XLOOKUP is better than VLOOKUP — the real answer is exact by default and it does not break when a column is inserted. Extra reps: Excel labs.
