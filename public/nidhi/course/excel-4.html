Analysis and the dashboard

This chapter produces the small dashboard you can already explain. The next chapter is the real one: you rebuild the Ferra HR workbook Cursor already made, cell by cell. Here you learn sort, filter, pivots, charts and Power Query so that file does not intimidate your.

Before any analysis

Sorting, filtering and duplicates

Unglamorous and used daily. The things worth actually knowing:

TaskHowThe trap
Sort by several columnsData → Sort, then Add Level. Sort by Source, then by Applied.Sorting a selection rather than the whole table scrambles the rows against each other. In a proper Table this cannot happen — another reason to use one.
FilterCtrl+Shift+L, then the dropdown arrows.A filtered view is not a saved report. Anyone opening the file sees it filtered and may not notice. Never send a filtered file as a report.
SUBTOTAL=SUBTOTAL(109, Candidates[FeeEUR])This is the one people do not know. SUM ignores filters; SUBTOTAL with a code of 109 sums only the visible rows. Put it above a filtered list and the total follows the filter.
Remove DuplicatesData → Remove DuplicatesIt deletes rows permanently. Always copy the sheet first. And tick only the columns that define a duplicate — ticking every column means only perfectly identical rows go, which is rarely what is meant.
Find duplicates without deleting=COUNTIF(Candidates[Email],[@Email])>1Safer: it flags them so a human decides. This is the one to use on candidate data, where a duplicate might be two real people with the same name.

On deduplicating candidates. Two rows with the same name are not necessarily the same person, and the same person can legitimately appear twice if they applied to two roles. The right key is an email address or a candidate ID, never a name. Deleting a row because the name matched is how a real applicant disappears from a process.

The fastest way to answer a question

PivotTables

A PivotTable answers "how many X by Y" in about four seconds, with no formulas. Insert → PivotTable, then drag fields into four boxes:

BoxWhat goes thereExample
RowsWhat to group by, down the sideSource
ColumnsA second grouping, across the topRoleID
ValuesWhat to measureCount of Name
FiltersA whole-table filter above the pivotRecruiter

Try it — this is a real pivot engine

Change the dropdowns and watch the table rebuild. This is the same mental model as the real thing: pick a grouping, pick a measure, pick how to summarise it.

The four settings that make a pivot look professional.

  1. Summarise Values By — right-click a number. It defaults to Count for text and Sum for numbers, and the default is often wrong. Sum of HireDays is a meaningless number; Average of HireDays is time to hire.
  2. Show Values As → % of Grand Total — turns counts into a source mix in one click. Try it in the dropdown above.
  3. PivotTable Options → Preserve cell formatting / For empty cells show 0 — stops the layout jumping on refresh and removes blank gaps.
  4. Refresh. A pivot does not update when the data changes. Alt+F5, or Data → Refresh All. Forgetting this is the single most common way a wrong number reaches a manager.

Grouping dates, and GETPIVOTDATA

Drop a date field into Rows and Excel offers to group by Years, Quarters and Months — that is a hiring-by-month chart with no formula at all. Right-click → Group to change it.

And when you need one number out of a pivot to put on a dashboard, clicking the cell writes GETPIVOTDATA. It looks alarming and it is simply "fetch this specific number from that pivot". It is more robust than a cell reference because it survives the pivot changing shape.

Make the eye go to the right cell

Conditional formatting

Home → Conditional Formatting. Four kinds are worth knowing, and one rule about all of them.

  • Highlight Cell Rules — greater than, text contains, duplicate values. The quick one.
  • Data bars — an in-cell bar. Excellent for time to hire: the long bars are the problem roles and no one has to read a number.
  • Colour scales — green-to-red across a range. Use sparingly; on a dense table it becomes decoration.
  • Icon sets — the traffic lights. Good for a status column a manager skims.
  • Use a formula — the powerful one. New Rule → Use a formula to determine which cells to format.

The formula rule, properly explained

To shade the whole row of anyone open for more than fourteen days, select A2:L7 and write one formula:

=AND($K2="Open", TODAY()-$E2>14)

The dollar signs are the entire trick. $K2 locks the column but not the row, so as the rule is applied across the row it keeps looking at column K, and as it moves down the rows it follows the row. Write K2 without the dollar and the rule drifts sideways into the wrong columns; write $K$2 and every row is judged by Asha's outcome.

The rule about all conditional formatting: it must encode a decision, not a mood. "Red means this needs chasing today" is useful. A rainbow across every number is noise, and a manager learns to ignore the whole file. One or two rules per sheet.

Charts that survive a manager

Choosing and building charts

QuestionChartWhy
How many applicants per source?Bar (horizontal)Long category names fit. Bar beats column whenever labels are words.
Is time to hire improving?LineTime on the x-axis means line. Always.
Where do candidates drop out?Funnel, or a bar sorted descendingShows the fall between stages, which is the actual question.
What is the source mix?Stacked bar — one bar, 100%Better than a pie: comparable across months and readable at four or more categories.
Offers vs accepts per recruiterClustered columnTwo series side by side, easy to compare.

Three chart habits to drop. Pie charts with more than four slices — nobody can compare similar-sized wedges; use a bar. Dual axes — two different scales on one chart can be made to show almost any relationship, which is why they are not trusted. 3-D anything — the perspective distorts the values it is meant to communicate.

Finishing a chart, in order

  1. Delete the chart title Excel generated and write a sentence instead. Not "Applicants by Source" but "Referrals are 17% of applicants and 50% of joiners". The title should be the finding.
  2. Delete the legend if there is one series. It is redundant ink.
  3. Delete the gridlines and add data labels instead, if the exact numbers matter.
  4. Sort the bars by value, descending. An unsorted bar chart makes the reader do work the chart should have done.
  5. Start the axis at zero. A truncated axis exaggerates differences. On a line chart of a rate this is the one that misleads most.

The same data, two titles

What most people submit

"Applicants by Source"

Describes the axes. The reader has to work out what it means, and most will not bother.

What gets your hired

"Referrals are 1 in 6 applicants but half of all joiners — worth a formal referral scheme"

States the finding and the recommendation. Same chart, same data. This sentence is the skill.

Sparklines and in-cell charts

Insert → Sparklines puts a tiny chart inside a single cell. A column of sparklines beside a table of roles shows each role's trend without five separate charts. Cheap, and it looks considered.

The skill that saves your a day a month

Power Query

Everything in chapter 1.3 cleaned data once. Power Query records the cleaning as steps and replays them on a new file. Learning it is the difference between a monthly report that costs your a morning and one that costs a click.

The loop, in five steps

  1. Get Data → From File → From Workbook (or Text/CSV). Point it at the ATS export.
  2. Transform Data — this opens the Power Query editor. Never click Load straight away; cleaning happens here, not in the sheet.
  3. Clean. Every click is recorded in the Applied Steps list on the right. Promote headers, remove the junk columns, set each column's data type, trim the text, replace values, filter out blanks.
  4. Close & Load To → Table, on a new sheet. The result arrives as a proper Table, already named.
  5. Next month: Data → Refresh All. Every step re-runs. Nothing is retyped.
TransformWhat it doesWhen you need it
Use First Row as HeadersPromotes row 1 to column namesAlmost every export.
Change TypeSets a column to date, whole number, textAlways. This is the step that fixes dates-stored-as-text at the source instead of with DATEVALUE.
Remove ColumnsDrops the fifty fields nobody readsEvery export has them.
Split Column by DelimiterTitle and city in one stepReplaces the whole LEFT/SEARCH exercise, permanently.
Replace Values / TrimFixes the dirty source columnReplaces the mapping-table trick for known typos.
Merge QueriesJoins two tables on a keyThis is XLOOKUP as a step. Left Outer keeps every candidate even without a matching role.
Append QueriesStacks tables on top of each otherTwelve monthly exports into one table. The moment this clicks, the yearly report takes minutes.
Unpivot ColumnsTurns columns into rowsThe one to remember. An export with a column per month is unusable; Unpivot turns it into Month / Value and makes it analysable. Interviewers notice this answer.
Group ByAggregates inside the queryWhen you only needs the summary, not 40,000 rows.

Merge vs Append, said once so it sticks. Merge adds columns — the same rows, more facts about each. Append adds rows — more records of the same shape. Merge for "bring the manager name in", Append for "add March to the file".

It is written in a language called M. You do not need to write M. You need to click the steps and know that the Advanced Editor is where the recorded code lives if something breaks.

Structure before numbers

How to lay out a dashboard

The structure is the thing being assessed, more than the formulas. Four sheets, each with one job:

SheetContainsRule
DataThe Candidates table. One row per person, one fact per column.Typed facts only. No formulas, no colour, no blank rows, no merged cells.
RolesOne row per requisition.The lookup table. Also typed only.
CalcPivots and helper formulas.The working. Nobody else needs to read it, and it can be hidden.
DashboardHeadline, cards, two or three charts, a flagged list.Not one typed number. Every cell points at Data or Calc.

The reading order of the dashboard sheet

  1. A sentence at the top. The finding, in words, built with & and TEXT so it updates itself. "6 applicants, 4 offers, 75% acceptance, 31 days average."
  2. A row of cards. Four to six big numbers: applicants, offers, acceptance, time to hire, agency spend. One number each, large, with a label beneath.
  3. The funnel. The six stage counts, as a sorted bar. This is the chart a hiring manager actually looks at.
  4. Two supporting charts. Source mix and time to hire by role. No more than two.
  5. The action list at the bottom. Everyone flagged for chasing, pulled in live with FILTER. This is the part that makes it a working tool rather than a report.

Things that quietly mark a file as amateur. Merged cells (they break sorting, filtering and every formula that touches them — use centre-across-selection instead). Numbers typed on the dashboard. Gridlines left on. Sheets named Sheet1. Eight colours. A chart with the title Excel generated. No date anywhere saying when the data is from.

Build the whole thing

This is the chapter's deliverable: a dashboard block where every cell is a formula pointing at the table. Ten cells. When all ten are right, you have the portfolio piece.

Giving the file to someone else

Making it hard to break

  • Data validation (Data → Data Validation → List) turns Source and Outcome into dropdowns. This is the real fix for the dirty-source problem — stop the bad data being typed in the first place. Point the list at a small lookup range so new values can be added without editing the rule.
  • Protect Sheet — unlock the few cells meant to be edited, then protect. Nobody overwrites a formula by accident.
  • Freeze Panes (View → Freeze Panes → Freeze Top Row) so headers stay visible. Ten seconds, and the file feels maintained.
  • Named ranges for anything a formula refers to repeatedly. =SUM(AgencyFees) reads better than =SUM(Calc!$M$2:$M$400) and does not break when the sheet moves.
  • A notes cell saying where the data came from and when it was pulled. It takes one line and it answers the first question anyone asks.
